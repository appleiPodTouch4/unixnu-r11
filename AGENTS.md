# Device agent guide — OPPO R11 (r11)

This repository owns the board DTS, the hardware values extracted from the
device's own firmware, component selection, the firmware inputs and the
partition geometry for the OPPO R11 (CPH1707 / model 16051, SDM660).

## Rules for this board

1. **No invented hardware values.** Every address, size and identity comes from
   `inputs/` (generated by `scripts/extract-inputs.py` from the OFP package) or
   from a device measurement recorded in `porting.toml`. When a value is not
   available, leave it out and record the measurement in `next_action`.
2. **FD base and size are fixed.** `0x9FC00000` + `0x300000` is the window the
   stock XBL reserves for `UEFI FD`. It appears in three places that must stay
   equal: `../uefi-r11/Resources/Configs/r11.toml`, `r11.dsc` and the BootShim
   compile flags. `scripts/check-r11.py` checks two of them.
3. **One contiguous DRAM range.** The ADT generator accepts exactly one
   `/memory` reg; the two physical banks are adjacent and are described as one
   range. `[payload] dram_size` must equal it.
4. **No `[[bootimg.dtb_node]]`.** The stock R11 tree already carries
   `/reserved-memory/splash_region`; adding it again makes `fdtput` fail.
5. **`fastboot boot`, not `fastboot flash boot`.** `boot` is 64 MiB, the payload
   is 192 MiB.

## Commands

```sh
python3 scripts/extract-inputs.py --ofp ../ofp_extracted     # refresh inputs/
python3 scripts/check-r11.py                                  # firmware preflight

cd ../UniXNU
./unixnu defconfig r11_defconfig -D ../UniXNU-r11
./unixnu status -D ../UniXNU-r11
./unixnu build firmware -D ../UniXNU-r11 --uefi ../uefi-r11-base --edk2 ../Mu_Basecore
./unixnu bootimg -D ../UniXNU-r11 --uefi ../uefi-r11-base --dtb ../uefi-r11/Platforms/OPPO/r11Pkg/DeviceTree/r11.dtb
```

## Record

Update `porting.toml` in the same change: hardware results go to the matching
area with `status = device-verified`, commands and revisions in `procedure`, and
the next measurement in `next_action`. Areas that stay untouched must keep their
`limits` accurate.
